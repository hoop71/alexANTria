## The Problem: Context Rot

Every coding session starts from scratch. You re-explain architecture, context bloats prompts, documentation rots, agents contradict each other. **Context rot is structural**—models degrade when context exceeds soft limits.

## The Solution: Three-Pool Architecture

Based on [RLM research](https://www.dbreunig.com/2026/02/09/the-potential-of-rlms.html), alexANTria separates three types of context:

<CardGrid stagger>
	<Card title="🔧 Programmatic Pool" icon="seti:config">
		**What agents can infer from code**

		Service boundaries, API contracts, architecture patterns—discoverable by reading implementations.
	</Card>
	<Card title="📝 Tokenized Pool" icon="document">
		**What must be written down**

		Patterns, conventions, the "how we do things"—explicit documentation that guides agents.
	</Card>
	<Card title="🧠 Intentional Pool" icon="star">
		**What only humans know**

		Strategy, constraints, "why" decisions were made—human knowledge that cannot be inferred.
	</Card>
</CardGrid>

## Why It Matters

At 30 agents (Gas Town scale): **30 agents reading code** (programmatic ✓) + **30 agents reading docs** (tokenized ✓ with Beads) + **30 agents needing strategy** (intentional ✗ stuck in your head).

alexANTria solves the intentional pool—capturing why decisions were made so agents don't need constant re-explanation.

**Start with what you need. Build higher when the audience emerges.**
