# Templates

Starting points for `/ant-init` generated files. **Edit before `install.sh`** to match your workflow.

## How It Works

`/ant-init` uses these templates. Placeholders like `{{PROJECT_NAME}}` get replaced with actual values.

## Template Types

### ANT-* Levels

3-level RLM structure:
- `ANT-PROGRAMMATIC.md.template` → Programmatic (file index, what exists)
- `ANT-TOKENIZED.md.template` → Tokenized (patterns and conventions)
- `ANT-INTENTIONAL.md.template` → Intentional (strategy and decisions)

Generated by `/ant-init`. Documentation hierarchy where higher levels constrain lower levels.

### Rules

Path-based guidance. Auto-loads when editing matching files:
- `rules/frontend.md.template` → `.claude/rules/frontend.md`
- `rules/backend.md.template` → `.claude/rules/backend.md`
- `rules/ai.md.template` → `.claude/rules/ai.md`

Passive context, not executable.

### Memory

- `CLAUDE.md.template` → `CLAUDE.md` (always-loaded hierarchy)

### External Context

- `ANT-EXTERNAL.md.template` → Marks externally-generated context (read-only)

## Customizing

### CLAUDE.md.template

Main context file. Customize hierarchy mappings, workflow sections.

### rules/*.template

Path-specific rules. Customize `paths:` frontmatter, "Read first" links, patterns.

## Add Your Own

Create templates for your domains:

**`rules/data.md.template`**
```markdown
---
paths:
  - "src/db/**/*"
---
# Data Layer Context
- Migrations reversible
- Use transactions
```

## Placeholders

| Placeholder | Replaced With |
|------------|---------------|
| `{{PROJECT_NAME}}` | Project name |
| `{{UX_DOC}}` | Detected UX doc |
| `{{ARCHITECTURE_DOC}}` | Architecture doc |

Missing docs: section omitted or `/ant-init` prompts.

## Sharing

Build stack-specific templates in `templates/stacks/`:

```
templates/stacks/
├── nextjs/
│   └── frontend.md.template
├── rails/
│   └── models.md.template
```
